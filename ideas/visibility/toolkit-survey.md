# How other toolkits model a hidden-but-in-tree component

Research for `ideas/visibility.md`, gathered 2026-09-05 against primary sources
(docs and source), not memory. "Unverified" marks a claim no primary source
confirmed. Per entry: **API** · **space** (does hidden take layout space; both
variants?) · **focus/input** · **gap** (does box spacing skip a hidden middle
child?) · **notable**.

## TUI toolkits

**Textual (Python).** API: two CSS rules, both exposed as Python booleans — `display: block|none` (`widget.display = False`) and `visibility: visible|hidden` (`widget.visible = False`). Space: `display:none` — "space will no longer be reserved for it" ([display](https://textual.textualize.io/styles/display/)); `visibility:hidden` — "Textual will reserve space for it, but won't display anything" ([dom.py](https://raw.githubusercontent.com/Textualize/textual/main/src/textual/dom.py)). Both variants. Focus/input: `Widget.focusable` requires `self.visible`; `Screen.focus_chain` walks `displayed_children` (filter `node.display == True`) and drops `visibility:hidden` nodes ([screen.py](https://raw.githubusercontent.com/Textualize/textual/main/src/textual/screen.py), [widget.py](https://raw.githubusercontent.com/Textualize/textual/main/src/textual/widget.py)); the compositor keeps `visibility:hidden` widgets out of the hit-test map, so no mouse either ([_compositor.py](https://raw.githubusercontent.com/Textualize/textual/main/src/textual/_compositor.py)). Gap: layouts iterate `displayed_children`, so a `display:none` child contributes nothing (Textual uses margins, not `gap`). Notable: `ContentSwitcher` uses the flag, not detachment — `self.get_child_by_id(old).display = False` ([_content_switcher.py](https://raw.githubusercontent.com/Textualize/textual/main/src/textual/widgets/_content_switcher.py)). "Children of an invisible container can be visible" via `visibility: visible` ([visibility](https://textual.textualize.io/styles/visibility/)).

**FTXUI (C++).** API: `Maybe(child, const bool* show)` decorator (boolean). Space: gone — `OnRender()` returns an empty `Node`; `OnEvent()` returns `false`; `Focusable()` returns `false` when hidden ([maybe.cpp](https://raw.githubusercontent.com/ArthurSonzogni/FTXUI/main/src/ftxui/component/maybe.cpp)). No "invisible-keeps-space" variant. Gap: `separator()`s are sibling elements, so a hidden middle child leaves its neighbouring separators (inferred from the element model; unverified).

**urwid (Python).** No visibility flag. Maintainers' answer to "hide without destroying": delete from `Pile`/`Columns` `.contents` and re-insert later, or wrap in `WidgetPlaceholder` and swap `original_widget` for an empty `Pile` ([issue #485 comments](https://api.github.com/repos/urwid/urwid/issues/485/comments)). `Columns` treats a 0 width as "hide corresponding column completely" ([manual](https://urwid.org/manual/widgets.html)). Gone-only, by detachment.

**ratatui (Rust).** Immediate mode: "every frame draws the UI anew"; no retained tree, so hiding = not rendering the widget that frame ([rendering concepts](https://ratatui.rs/concepts/rendering/)). N/A for focus/gap.

**notcurses (C).** No hide flag. Man page: a plane "can be moved off-screen entirely"; `ncplane_reparent(n, NULL)` makes it "the root plane of a new, unrendered stack" ([notcurses_plane(3)](https://notcurses.com/notcurses_plane.3.html)); USAGE.md lists offscreen / `move_below` / reparent-off-pile as the three hide idioms ([USAGE.md](https://github.com/dankamongmen/notcurses/blob/master/USAGE.md)). No layout, so space N/A.

**tview (Go).** `Flex` items have no visibility field (`flexItem{Item, FixedSize, Proportion, Focus}`); a `nil` item is a spacer that "will still consume screen space" ([flex.go](https://raw.githubusercontent.com/rivo/tview/master/flex.go)). `Pages` has a per-page boolean: `AddPage(..., visible)`, `HidePage`/`ShowPage`; `Draw` skips `!page.Visible`, and `Focus` lands on the topmost visible page ([pages.go](https://raw.githubusercontent.com/rivo/tview/master/pages.go)). Pages overlap, so space is N/A.

**Bubble Tea / lipgloss (Go).** Elm architecture; `View()` returns a string, no component tree or visibility API — hide by not concatenating ([README](https://raw.githubusercontent.com/charmbracelet/bubbletea/main/README.md)).

**blessed (node).** API: `hide()`/`show()`/`toggle()`, `hidden` flag, `visible` getter that also walks ancestors for `hidden`/`detached` ([element.js](https://raw.githubusercontent.com/chjj/blessed/master/lib/widgets/element.js)). Space: absolute positioning; `_getCoords` returns nothing when hidden. Focus/input: `hide()` calls `screen.rewindFocus()` if focused; `focusNext` filters `!el.detached && el.visible`; mouse routing `continue`s on hidden ([screen.js](https://raw.githubusercontent.com/chjj/blessed/master/lib/widgets/screen.js)). Gap: `Layout` widget has no explicit hidden check ([layout.js](https://raw.githubusercontent.com/chjj/blessed/master/lib/widgets/layout.js)) — behaviour unverified.

**Ink (React CLI).** `<Box display="flex"|"none">` — "Set this property to `none` to hide the element" ([readme](https://raw.githubusercontent.com/vadimdemedes/ink/master/readme.md)); mapped to `Yoga.DISPLAY_NONE` ([styles.ts](https://raw.githubusercontent.com/vadimdemedes/ink/master/src/styles.ts)), so gone (Yoga semantics). No invisible variant. Focus: the focus manager only checks `isActive` — no display/visibility check ([App.tsx](https://raw.githubusercontent.com/vadimdemedes/ink/master/src/components/App.tsx)), so a `display:none` component stays Tab-reachable unless the app passes `useFocus({isActive:false})` (inferred).

**Lanterna (Java).** `Component.setVisible(boolean)`: "The exact behavior of an invisible component will depend on the layout manager; some will just ignore invisible components where others leave an empty space in their place. Invisible components cannot get input focus." ([Component.java](https://raw.githubusercontent.com/mabe02/lanterna/master/src/main/java/com/googlecode/lanterna/gui2/Component.java)). `LinearLayout` filters `Component::isVisible` first and applies `spacing * (visible.size() - 1)` — no double gap ([LinearLayout.java](https://raw.githubusercontent.com/mabe02/lanterna/master/src/main/java/com/googlecode/lanterna/gui2/LinearLayout.java)).

**Turbo Vision (magiblot/tvision).** State bit `sfVisible`; `hide()`/`show()` call `setState(sfVisible, …)`, which propagates `sfExposed`, calls `drawHide`/`drawShow`, and `owner->resetCurrent()` for selectable views ([tview.cpp](https://raw.githubusercontent.com/magiblot/tvision/master/source/tvision/tview.cpp)). `TGroup::findNext` requires `(state & (sfVisible|sfDisabled)) == sfVisible` — hidden views skipped by focus cycling ([tgroup.cpp](https://raw.githubusercontent.com/magiblot/tvision/master/source/tvision/tgroup.cpp)). Absolute coordinates, no layout manager.

**ncurses panels.** `hide_panel` "removes the given panel from the panel stack and thus hides it from view. The PANEL structure is not lost" ([panel(3x)](https://invisible-island.net/ncurses/man/panel.3x.html)). Stack-only concept; no layout/focus.

## GUI toolkits

**Android View.** Enum `setVisibility(VISIBLE|INVISIBLE|GONE)`: INVISIBLE "still takes up space for layout purposes"; GONE "doesn't take any space" ([View.java](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/core/java/android/view/View.java)). Both variants. Focus: `hasFocusable` — "Only VISIBLE views … are considered focusable" ([View docs mirror](https://stuff.mit.edu/afs/sipb/project/android/docs/reference/android/view/View.html)). Gap: `LinearLayout` measure/layout `continue`s on GONE; dividers use `allViewsAreGoneBefore` so no divider is drawn beside a GONE child ([LinearLayout.java](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/core/java/android/widget/LinearLayout.java)). Switcher: `ViewAnimator.showOnly` sets `child.setVisibility(View.GONE)`, children stay attached ([ViewAnimator.java](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/core/java/android/widget/ViewAnimator.java)).

**Swing/AWT.** Boolean `setVisible`. Per-layout: `BoxLayout` gives invisible children a `SizeRequirements(0,0,0)` — zero size but not removed, and its spacing is done with strut/glue *components*, so a strut beside a hidden child stays (double gap) ([BoxLayout.java](https://raw.githubusercontent.com/openjdk/jdk/master/src/java.desktop/share/classes/javax/swing/BoxLayout.java)); `GridBagLayout` `continue`s on `!isVisible()` ([GridBagLayout.java](https://raw.githubusercontent.com/openjdk/jdk/master/src/java.desktop/share/classes/java/awt/GridBagLayout.java)); `FlowLayout` adds `hgap` only between visible components ([FlowLayout.java](https://raw.githubusercontent.com/openjdk/jdk/master/src/java.desktop/share/classes/java/awt/FlowLayout.java)); `GroupLayout.setHonorsVisibility` (default `true` = gone; `false` = keep space, also per-component) is the only explicit both-variants knob ([GroupLayout](https://docs.oracle.com/en/java/javase/21/docs/api/java.desktop/javax/swing/GroupLayout.html)). Focus: traversal policy `accept` requires visible, displayable, enabled, focusable ([ContainerOrderFocusTraversalPolicy](https://docs.oracle.com/en/java/javase/21/docs/api/java.desktop/java/awt/ContainerOrderFocusTraversalPolicy.html)). Switchers use the flag: `CardLayout.show` toggles `setVisible` ([CardLayout.java](https://raw.githubusercontent.com/openjdk/jdk/master/src/java.desktop/share/classes/java/awt/CardLayout.java)); `BasicTabbedPaneUI.setVisibleComponent` likewise ([BasicTabbedPaneUI.java](https://raw.githubusercontent.com/openjdk/jdk/master/src/java.desktop/share/classes/javax/swing/plaf/basic/BasicTabbedPaneUI.java)).

**JavaFX.** Two booleans: `visible` ("Invisible nodes never receive mouse events or keyboard focus and never maintain keyboard focus when they become invisible") and `managed` (unmanaged = parent ignores it for layout) ([Node](https://openjfx.io/javadoc/21/javafx.graphics/javafx/scene/Node.html)). Invisible-only keeps space; `visible=false && managed=false` is the "gone" idiom. Gap with `managed=false` in `VBox`: unverified.

**Qt.** Boolean `hide()`/`setVisible`; `QSizePolicy::setRetainSizeWhenHidden` (default `false`): "the layout will not be changed by hiding the widget" ([QSizePolicy](https://doc.qt.io/qt-6/qsizepolicy.html)). Mechanism: `QWidgetItem::isEmpty()` = `isHidden() && !retainSizeWhenHidden() || isWindow()` ([qlayoutitem.cpp](https://code.qt.io/cgit/qt/qtbase.git/plain/src/widgets/kernel/qlayoutitem.cpp)); `QBoxLayout::setupGeom` sets `spacing = 0` for empty items and spaces only from `previousNonEmptyIndex` — no double gap ([qboxlayout.cpp](https://code.qt.io/cgit/qt/qtbase.git/plain/src/widgets/kernel/qboxlayout.cpp)). Both variants. Focus for hidden widgets: unverified from docs. `QStackedLayout` "only the current widget is visible" (StackOne) ([QStackedLayout](https://doc.qt.io/qt-6/qstackedlayout.html)).

**GTK4.** Boolean `gtk_widget_set_visible`; `gtk_widget_should_layout` returns false for invisible children, so layout managers skip them ([should_layout](https://docs.gtk.org/gtk4/method.Widget.should_layout.html)); `GtkBoxLayout` computes `(n_visible_children - 1) * spacing` — no double gap ([gtkboxlayout.c](https://gitlab.gnome.org/GNOME/gtk/-/raw/main/gtk/gtkboxlayout.c)). Gone-only; no keep-space flag. `GtkStack` hides pages with the container-only `gtk_widget_set_child_visible(FALSE)` ([gtkstack.c](https://gitlab.gnome.org/GNOME/gtk/-/raw/main/gtk/gtkstack.c), [set_child_visible](https://docs.gtk.org/gtk4/method.Widget.set_child_visible.html)). Focus skip for invisible widgets: unverified from docs.

**CSS.** `display:none` — "rendered as though the element did not exist", removed from accessibility tree ([MDN display](https://developer.mozilla.org/en-US/docs/Web/CSS/display)); `visibility:hidden` keeps its box, "cannot receive focus"; `visibility:collapse` removes space for table rows/flex items only ([MDN visibility](https://developer.mozilla.org/en-US/docs/Web/CSS/visibility)). Both variants. Flex `gap` with a `display:none` child: follows from "does not exist" (no flex item, no gap) — inferred, spec sentence not fetched.

**Vaadin Flow.** Boolean `setVisible(false)`: already-rendered element gets the `hidden` attribute (kept in DOM; `display:none` via CSS), unrendered ones create no element until visible; children inherit; invisible components "won't receive updates from the client side", server-side updates resume when visible ([docs v24](https://vaadin.com/docs/v24/flow/create-ui/basic-features), [issue #3143](https://github.com/vaadin/flow/issues/3143)). Gone-only.

**Flutter.** `Visibility(visible:, maintainSize, maintainState, maintainAnimation, maintainSemantics, maintainInteractivity, replacement)` — default replaces the child with `SizedBox.shrink` (out of tree, gone); `maintainSize` keeps space; `Offstage` lays out but takes no room, no hit-testing, yet "Offstage children are still active: they can receive focus and have keyboard input directed to them" ([Visibility](https://api.flutter.dev/flutter/widgets/Visibility-class.html), [Offstage](https://api.flutter.dev/flutter/widgets/Offstage-class.html)). Both variants, richest knob set.

**SwiftUI.** `.hidden()`: "invisible and can't receive or respond to interactions … remain in the view hierarchy and affect layout"; docs say use `if` to remove ([hidden()](https://developer.apple.com/documentation/swiftui/view/hidden())). Both, via two mechanisms.

**Jetpack Compose.** No flag; GONE = conditional composition (`if`), INVISIBLE = `Modifier.alpha(0f)` or the new `Modifier.visible()` in compose-ui 1.11.0-alpha01, which "skip[s] drawing … without affecting the space it occupies" ([release notes](https://developer.android.com/jetpack/androidx/releases/compose-ui), [article](https://proandroiddev.com/from-view-invisible-to-modifier-visible-rethinking-visibility-%EF%B8%8Fin-jetpack-compose-7957650e4d70)).

**WPF.** Enum `Visibility.Visible|Hidden|Collapsed` — Hidden reserves space, Collapsed doesn't ([Visibility](https://learn.microsoft.com/en-us/dotnet/api/system.windows.visibility)). Non-Visible elements "do not participate in input events (or commands), do not influence either the Measure or Arrange passes … are not in a tab sequence, and will not be reported in hit testing" ([UIElement.Visibility](https://learn.microsoft.com/en-us/dotnet/api/system.windows.uielement.visibility)) — note Hidden still reserves space per the enum doc.

**WinForms.** Boolean `Control.Visible`. `CanSelect` requires "the control itself is visible and enabled, and all its parent controls are visible and enabled" ([CanSelect](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.control.canselect)). `FlowLayoutPanel` reflows around invisible controls; `TableLayoutPanel` cell/column behaviour is forum-sourced only ([MSDN thread](https://learn.microsoft.com/en-us/archive/msdn-technet-forums/18b2b207-5ff5-4ca3-8ccb-a07c7c333fcf)) — treat as unverified.

**Tk.** No flag; `pack forget` / `grid forget` unmap and unmanage (gone); `grid remove` does the same but "the configuration options for that window are remembered" ([grid](https://www.tcl-lang.org/man/tcl8.6/TkCmd/grid.htm), [pack](https://www.tcl-lang.org/man/tcl8.6/TkCmd/pack.htm)). Focus traversal skips a window "if it is disabled, if it has no key bindings, or if it is not viewable" ([-takefocus](https://www.tcl-lang.org/man/tcl8.6/TkCmd/options.htm)).

**AppKit.** `NSView.isHidden`: "does not receive input events", stays in `subviews`, frame retained; a hidden first responder hands off to `nextValidKeyView` ([isHidden](https://developer.apple.com/documentation/appkit/nsview/ishidden)). `NSStackView.detachesHiddenViews` (default `true`) removes hidden arranged views from layout into `detachedViews`, so spacing collapses; `false` keeps their space ([detachesHiddenViews](https://developer.apple.com/documentation/appkit/nsstackview/detacheshiddenviews)). Both variants.

## Dominant pattern

(a) Roughly half offer both: Textual, Android, WPF, CSS, Qt, Flutter, SwiftUI, Compose (new), JavaFX, AppKit, Swing (`GroupLayout` only). The rest are gone-only (FTXUI, Ink, GTK4, Vaadin, Lanterna's `LinearLayout`, Tk, urwid-by-detachment) or have no tree at all (ratatui, Bubble Tea, notcurses). (b) Where a single boolean exists, "gone" is the overwhelming default — Qt, GTK4, Swing layouts other than `BoxLayout`, WinForms flow, AppKit stack views, Flutter `Visibility`, Textual's `display`; only JavaFX `visible`, SwiftUI `.hidden()` and CSS `visibility` default to keep-space, and each pairs it with a separate gone mechanism (`managed`, `if`, `display`). Keep-space is almost always the *opt-in* (`retainSizeWhenHidden`, `maintainSize`, `setHonorsVisibility(false)`, `detachesHiddenViews = false`). (c) Every toolkit with a documented focus model excludes hidden components from traversal, hit-testing and input (Textual, blessed, Lanterna, Turbo Vision, Android, Swing, JavaFX, WPF, WinForms, Tk, AppKit, Vaadin); the two documented exceptions are Flutter's `Offstage` (still focusable, by design) and Ink (focus manager ignores `display`). Several also actively *repair* focus on hide (blessed `rewindFocus`, AppKit `nextValidKeyView`, Turbo Vision `resetCurrent`, JavaFX "never maintain keyboard focus"). (d) Box layouts that treat the hidden child as gone consistently count spacing over *visible* children only — Qt `QBoxLayout`, GTK `GtkBoxLayout`, Lanterna `LinearLayout`, AWT `FlowLayout`, Android `LinearLayout` (dividers included), AppKit stack views; the one notable double-gap trap is Swing `BoxLayout`, whose spacing is made of strut *components* that don't hide with their neighbour. Switcher widgets split evenly between the flag (Textual `ContentSwitcher`, Swing `CardLayout`/`JTabbedPane`, Android `ViewAnimator`, Qt `QStackedLayout`, GTK `GtkStack` via `child-visible`) and detachment (urwid, Flutter's default `Visibility`, SwiftUI/Compose conditionals, AppKit's `detachesHiddenViews`).
